# Flappy Bird Clone

A playable Flappy Bird clone written in **Python + pygame**, featuring fully
**custom, procedurally generated sprites** and synthesized sound effects.

![sprites](assets/bird.png) ← the bird, built at runtime and saved to `assets/`

## Features

- Custom vector-drawn sprites (bird, pipes, scrolling ground, sky with sun
  and clouds) generated by the code and cached as PNG files.
- Synthesized sound effects (flap, point, hit) generated at first run.
- Classic gameplay: tap to flap, avoid pipes, survive as long as you can.
- **Increasing difficulty** — as your score grows, pipes speed up and the
  gap tightens.
- Full game states: *Ready* → *Playing* → *Game Over* with restart.
- Persistent **best score** saved to `best_score.txt`.
- Rotating bird animation, cloud parallax, and an impact flash on collision.

## Requirements

- Python 3.9+
- [pygame](https://www.pygame.org/wiki/GettingStarted) ≥ 2.6

## Installation

```bash
cd flappybird-clone
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

## How to run

```bash
# activate the venv, then:
./venv/bin/python main.py
```

**Controls**

| Action        | Input                          |
|---------------|--------------------------------|
| Flap / start  | Left click, **Space**, or **↑** |
| Restart       | Left click / Space after death |
| Quit          | **Esc** or close the window    |

## Web version (pygbag)

The same game can run **in the browser** via [pygbag](https://pygame-web.github.io/),
which compiles Python + pygame to WebAssembly. The code is pygbag-aware out of
the box:

- The main loop is asynchronous (`await asyncio.sleep(0)` per frame) so the
  WASM renderer can copy the screen to the canvas.
- Procedural assets are pre-bundled, so none are regenerated in the browser.
- Audio is unlocked on the first user click/keystroke (browser autoplay
  policy).

### Build it yourself

```bash
./web_build.sh      # installs pygbag in build/pygbag-venv, then builds
python3 -m http.server -d build/web 9000   # open http://localhost:9000
```

The finished static site is written to `build/web/` — deploy that folder to any
static host.

### One-click hosting (GitHub Actions)

The `.github/workflows/pygbag-pages.yml` workflow builds the game and
**auto-deploys to GitHub Pages** on every push to `master`. Once enabled (repo
Settings → Pages → Source: *GitHub Actions*), it will be playable at:

```
https://<your-username>.github.io/<repo-name>/
```

## Project structure

```
flappybird-clone/
├── main.py          # game loop, logic, rendering, HUD
├── settings.py      # all tunable constants & configuration
├── sprites.py       # procedural sprite + sound generation
├── requirements.txt
├── assets/          # generated sprites & sounds (auto-created)
│
├── web_build.sh     # builds the browser version with pygbag
├── pygbag.ini       # pygbag build config (which files to ignore)
└── build/web/       # web build output (generated, git-ignored)
```

## Customizing the art

The sprites are drawn in `sprites.py`. Tweak colors in `settings.py` or edit
the drawing functions, then regenerate with:

```bash
./venv/bin/python sprites.py   # force-regenerates all assets
```

You can also replace any file in `assets/` with your own art — the game
loads whichever files are present.
